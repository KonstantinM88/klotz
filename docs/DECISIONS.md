# Decision log

## D-001 — Демо без админки и обязательной БД

- Статус: принято
- Дата: 2026-09-24
- Решение: первая демонстрационная версия использует локальный типизированный контент и не требует Neon, Prisma runtime, CMS или CRM.
- Причина: для клиентской презентации важнее визуальная сила, структура, скорость, реальные материалы и conversion flow. БД не добавляет видимой ценности, но повышает время и риск.
- Последствие: данные доступны через интерфейсы, чтобы позже заменить local repository на Prisma repository без переписывания страниц.

## D-002 — На первом этапе только KLOTZ.mobi

- Статус: принято
- Дата: 2026-09-24
- Решение: master prompt реализует KLOTZ.mobi. Сайт Kaffeehaus Meuschau не входит в демо.
- Причина: по Kaffeehaus пока нет подтверждённых адреса, характеристик, фотографий и условий аренды.
- Последствие: UI KLOTZ не должен превращаться в универсальный шаблон, но инфраструктурные primitives остаются пригодны для отдельной второй марки.

## D-003 — Стабильный стек вместо release candidate

- Статус: принято
- Дата: 2026-09-24
- Решение: baseline Next.js 16.3.6, React 19.3.0 и Prisma 7.10.0. Prisma 8 RC не используется.
- Причина: заказчику нужна надёжность, а не экспериментальный major release.

## D-004 — Реальные референсы нельзя заменять AI-визуализацией

- Статус: принято
- Дата: 2026-09-24
- Решение: AI-графика допустима для нейтральных фонов, схем и явно отмеченных concept visuals. Реальные проекты, команда и showroom показываются только реальными материалами с подтверждёнными правами.

## D-005 — Немецкий public-first

- Статус: принято
- Дата: 2026-09-24
- Решение: весь публичный демо-контент — естественный немецкий `de-DE`. Русский используется только в рабочей документации.

## D-006 — Premium означает точность, а не визуальный шум

- Статус: принято
- Дата: 2026-09-24
- Решение: архитектурная сетка, сильная типографика, крупные реальные фотографии, материал-фактура и аккуратные micro-interactions. Не использовать чрезмерный parallax, autoplay-видео, тяжёлые WebGL-сцены и шаблонную «чёрно-золотую роскошь».

## D-007 — Главная без hero carousel и рекламных pop-up

- Статус: принято
- Дата: 2026-09-24
- Решение: один сильный hero с реальной фотографией, ясным H1 и двумя CTA. Не использовать carousel, полноэкранный cookie wall и автоматический campaign pop-up.
- Причина: быстрее LCP, яснее позиционирование, меньше визуального шума и лучше мобильная конверсия.

## D-008 — Визуальное направление `Präzision. Raum. Vertrauen.`

- Статус: принято
- Дата: 2026-09-24
- Решение: KLOTZ blue + graphite + warm white, архитектурная сетка, крупные реальные изображения, оригинальная линейная графика процесса.
- Причина: соединяет premium-подачу производителя с доверием к региональному Fachbetrieb и не разрушает узнаваемость существующего бренда.

## D-009 — ESLint 9 вместо опубликованного ESLint 10

- Статус: принято
- Дата: 2026-09-24
- Решение: использовать ESLint 9.39.5 с `eslint-config-next` 16.3.6.
- Причина: strict peer resolution выявил, что транзитивный `eslint-plugin-import` пока допускает ESLint только до major 9. Использование `--force` или legacy peer resolution создало бы неподтверждённую конфигурацию.

## D-010 — TypeScript 6 вместо опубликованного TypeScript 7

- Статус: принято
- Дата: 2026-09-24
- Решение: использовать TypeScript 6.0.3.
- Причина: текущая цепочка `eslint-config-next` → TypeScript ESLint допускает TypeScript `<6.1`. TypeScript 7 не проходит strict peer resolution, поэтому не используется через `--force`.

## D-011 — jsdom 29 для локального Node 22.14

- Статус: принято
- Дата: 2026-09-24
- Решение: использовать jsdom 29.0.1 в тестовой среде.
- Причина: jsdom 30 требует Node 22.22.2+, а текущий локальный runtime — Node 22.14.0. jsdom 29 поддерживает Node 22.13+ и не влияет на production bundle.

## D-012 — Публичное индексирование демо выключено по умолчанию

- Статус: принято
- Дата: 2026-09-24
- Решение: metadata и `robots.txt` запрещают индексирование, пока `ALLOW_INDEXING` не будет явно установлен в `true`.
- Причина: черновые тексты, legacy-фотографии и юридические данные ещё не прошли клиентскую проверку; демо не должно случайно конкурировать с действующим сайтом.

## D-013 — Локальные реальные фотографии, разрешение только для презентации

- Дата: 2026-09-24. Статус: принято по явной команде пользователя.
- Сохранены 19 изображений/логотип с URL-источниками, SHA-256 оригиналов, размерами и `client-presentation-approved` в `content/assets-manifest.json`. Оптимизированные WebP отдаются локально; исходные ответы сохранены в `content/legacy/originals`.
- Hero использует отдельную фотографию ламельной террасы, а не рекламный коллаж. Подборки не дополнены придуманными сроками, площадью, ценами или отзывами. AI-генерация не потребовалась.
- Фото `standort` оказалось фотографией команды; оно не используется как фотография showroom. `zaun-detail` также не показывается. Наличие файла в архиве не означает его публикацию.
- Для бизнеса: лучше — узнаваемость и реальные материалы; риск остаётся в правах для будущего production.

## D-014 — Содержательная презентация без индексации черновиков

- Дата: 2026-09-24. Статус: принято; уточняет D-012.
- Светлая архитектурная вёрстка, оригинальный логотип, 21 страница услуг, 4 референсные подборки, 4 полные статьи и 12 тем в редакционном плане.
- Все новые тексты — редакционные draft, привязанные к источникам и без обещаний технических характеристик. Полные паспорта проектов пока не подтверждены.
- Индексация выключена в коде: noindex metadata и HTTP, robots disallow, пустой sitemap. `ALLOW_INDEXING` больше не включает её. Для запуска нужен отдельный проверяемый этап.
- LocalBusiness/Article/FAQ JSON-LD исключены до подтверждения фактов; оставлены навигационные BreadcrumbList. SEO-оценка Lighthouse может снижаться из-за намеренного noindex.
- Для бизнеса: лучше — ясный путь от услуги к заявке; безопаснее — демо не конкурирует с действующим сайтом.

## D-015 — Проверка формы без имитации настоящей отправки

- Дата: 2026-09-24. Статус: принято.
- Общая Zod-схема на клиенте и `POST /api/inquiries`: проверка origin, размера JSON, полей, honeypot, времени заполнения и process-local лимит запросов.
- Передаются тестовые поля и metadata вложений, но не файлы; нет email, хранения, CRM, аналитики или логирования содержимого. Успех явно говорит «nicht versendet oder gespeichert».
- `DEMO_MODE=false` возвращает 503; production delivery не включается переключателем. Process-local rate limit — защита демо, не распределённая production-защита.
- Для бизнеса: лучше — проверяемый сценарий; рискованнее было бы выдавать demo-success за полученную заявку.

## D-016 — Воспроизводимый browser QA

- Дата: 2026-09-24. Статус: принято.
- Добавлены только dev dependencies: Playwright 1.63.0 для Chromium desktop/mobile, axe 4.13.0 для доступности, Lighthouse 13.5.0 для метрик. UI runtime-зависимости не расширены.
- Для полного QA выбран Node 24.21.0: установленный системный 22.14 недостаточен для Lighthouse. Глобальный Node не заменялся.
- Browser приложения не предоставил доступного браузера; использован локальный Playwright. Скриншоты и отчёты сохраняются локально, не публикуются.
- Для бизнеса: лучше — дефекты формы и узких экранов ловятся до показа; эти проверки не заменяют ручной screen-reader и реальные устройства перед production.

## D-017 — Не загружать валидацию формы на каждой странице

- Дата: 2026-09-24. Статус: принято после Lighthouse.
- Автопредзагрузка ссылки на заявку подтягивала Zod даже на главную. Для CTA формы prefetch выключен, общая схема загружается в браузер при первой попытке отправки. Серверная проверка остаётся обязательной.
- Zod работает с `jitless=true`: CSP не ослабляется через `unsafe-eval`. Добавлены иконка вкладки из оригинального логотипа и высокий приоритет главных изображений.
- Для бизнеса: лучше — меньше ненужного JavaScript на первом экране; небольшой дополнительный запрос схемы выполняется только при проверке формы, под состоянием «Wird geprüft …».
