## D-021 — Компактный запуск AI-консультанта на главной

- По запросу пользователя видимая надпись `Projektlotse` убрана только с плавающей кнопки. Название внутри диалога оставлено для ясности. Кнопка стала круглой и полупрозрачной; доступное немецкое имя `KI-Beratung öffnen` сохраняет понятность для клавиатуры и screen reader.
- При первом открытии главной кнопка появляется через 5,5 секунды. На внутренних страницах доступна сразу; после первого появления при возврате на главную повторно не скрывается. Это не pop-up: диалог открывается только по нажатию.
- Однократная анимация появления и два мягких световых импульса выполнены CSS без новой зависимости; при `prefers-reduced-motion: reduce` движение отключено. Постоянной пульсации нет, чтобы не отвлекать от контента.
- Для бизнеса: **лучше** — мобильная фотография и CTA меньше перекрываются. **Рискованнее** — значок без подписи может быть менее очевиден новым посетителям; проверить это на клиентском показе и при необходимости вернуть короткую метку.

## D-019 — Проектный консультант: реальный AI с честным демо-режимом

- Пользователь запросил AI-ассистента для клиентской демонстрации. При первом внедрении ключа не было; 25.09 пользователь добавил его в локальный `.env`, и один синтетический русский вопрос успешно проверен через реальный API. Ключ не выводится и не отслеживается Git.
- Визуальный `Projektlotse` ведёт посетителя к подходящему разделу или demo-форме. При `OPENAI_API_KEY` серверный маршрут использует OpenAI Responses API (`gpt-5.4-mini`, `store: false`) и prompt из существующего content repository. Ключ не попадает в браузер или Git. Без ключа доступны узкие заранее подготовленные ответы с явной меткой `Geführte Demoantworten · keine Live-KI`; система не притворяется реальной AI-моделью.
- Интерфейс сайта и элементы управления диалогом — на немецком; ответ консультанта, подпись его ссылки и ошибки после вопроса — на языке последнего вопроса. Live AI получает это правило в серверном `instructions`; сценарные ответы локализованы для DE/EN/RU, другие языки без AI не обещаются. Без выдуманных цен, сроков, обещаний отправки заявки и сбора контактов в чате. Email/телефон блокируются перед передачей провайдеру; пользователь предупреждён о передаче текста вопроса при активной AI. Текст ответа выводится как обычный текст, ссылки на страницы выбирает сервер из известного списка.
- Прокрутка ограничена внутренней областью истории: при новой реплике показывается её начало, даже если длинный ответ не помещается целиком. Возврат фокуса в поле ввода не меняет положение прокрутки.
- Для продолжения диалога браузер отправляет до семи последних реплик (вопросы и успешные ответы). Сервер проверяет роли и длину, передаёт историю как непривилегированный текст внутри одного user input; сообщения из браузера не получают системного/assistant-приоритета в API.
- Демо ограничивает длину/число сообщений и запросы в минуту в памяти процесса. Для публичного сервиса потребуются распределённый лимитер, юридическая проверка передачи данных, мониторинг стоимости и предметные проверки ответов.
- Для бизнеса: **лучше** — наглядная навигация по услугам и дополнительный путь к заявке. **Рискованнее** — свободные AI-ответы и внешняя передача вопросов при активном ключе; до production нужны контроль качества и privacy review.

## D-018 — Новый редакционный дизайн вместо facelift

- Основание: пользователь отклонил близость предыдущего оформления к legacy и запросил самостоятельный современный профессиональный редизайн.
- Full-bleed фотография, крупная типографика, графит/тёплая бумага/лаймовый акцент, асимметричная редакционная подача проектов. Оригинальный логотип сохраняется.

- Для бизнеса: лучше — заметная смена образа и акцент на реальных работах. Риск — новый акцентный цвет и смелая композиция требуют визуального одобрения; версия остаётся локальным демо.

## D-001 — Демо без админки и обязательной БД

- Статус: принято
- Дата: 2026-09-24
- Решение: первая демонстрационная версия использует локальный типизированный контент и не требует Neon, Prisma runtime, CMS или CRM.

- Последствие: данные доступны через интерфейсы, чтобы позже заменить local repository на Prisma repository без переписывания страниц.

## D-009 — ESLint 9 вместо опубликованного ESLint 10

- Статус: принято
- Дата: 2026-09-24

## D-010 — TypeScript 6 вместо опубликованного TypeScript 7

- Статус: принято
- Дата: 2026-09-24
- Решение: использовать TypeScript 6.0.3.
- Причина: текущая цепочка `eslint-config-next` → TypeScript ESLint допускает TypeScript `<6.1`. TypeScript 7 не проходит strict peer resolution, поэтому не используется через `--force`.

## D-011 — jsdom 29 для локального Node 22.14

- Статус: принято
- Дата: 2026-09-24
- Решение: использовать jsdom 29.0.1 в тестовой среде.
- Причина: jsdom 30 требует Node 22.22.2+, а текущий локальный runtime — Node 22.14.0. jsdom 29 поддерживает Node 22.13+ и не влияет на production bundle.

## D-012 — Публичное индексирование демо выключено по умолчанию

## D-015 — Проверка формы без имитации настоящей отправки

## D-017 — Не загружать валидацию формы на каждой странице

- Дата: 2026-09-24. Статус: принято после Lighthouse.
- Автопредзагрузка ссылки на заявку подтягивала Zod даже на главную. Для CTA формы prefetch выключен, общая схема загружается в браузер при первой попытке отправки. Серверная проверка остаётся обязательной.
- Zod работает с `jitless=true`: CSP не ослабляется через `unsafe-eval`. Добавлены иконка вкладки из оригинального логотипа и высокий приоритет главных изображений.
- Для бизнеса: лучше — меньше ненужного JavaScript на первом экране; небольшой дополнительный запрос схемы выполняется только при проверке формы, под состоянием «Wird geprüft …».
